# Parte 1: RFC-004: Documentação de APIs (OpenAPI/Swagger) e Coleções de Teste

**Autor:** [Seu Nome/Sua Equipe]
**Data:** 24 de Março de 2026
**Status:** 🟡 Em Revisão (Aberto para Comentários)
**Componentes Afetados:** API Gateway, Auth Service (e futuros microsserviços)
**Stack:** Springdoc OpenAPI 2.x, Swagger UI, Postman

### 1. Sumário Executivo
Esta RFC propõe a padronização da documentação das APIs RESTful do sistema Beauty & Wellness utilizando a especificação **OpenAPI 3.0** via biblioteca `springdoc-openapi`. Além disso, define a estratégia de consolidação da interface gráfica (Swagger UI) no **API Gateway** e o fornecimento de arquivos padronizados do Postman no repositório.

### 2. Desenho da Solução (OpenAPI / Swagger)

Como temos uma arquitetura distribuída, o cliente (ou avaliador) não deve precisar acessar a porta de cada microsserviço individualmente para ler a documentação.

*   **Nos Microsserviços (ex: Auth Service):**
    *   Adicionaremos a dependência `springdoc-openapi-starter-webmvc-api`.
    *   Cada serviço irá gerar o seu próprio contrato JSON dinamicamente no endpoint `/v3/api-docs`.
    *   Utilizaremos as anotações `@Operation`, `@ApiResponses` e `@Schema` nos *Controllers* e *DTOs* para descrever os payloads e códigos de erro HTTP de forma rica.
*   **No API Gateway:**
    *   Adicionaremos a dependência `springdoc-openapi-starter-webflux-ui` (pois o gateway é reativo).
    *   O Gateway será configurado para **agregar** as documentações. Ao acessar `http://localhost:8080/swagger-ui.html`, haverá um *dropdown* (Select a definition) no canto superior direito permitindo alternar entre a documentação do "Auth Service", "Catalog Service", etc., tudo em uma única tela.

### 3. Desenho da Solução (Postman)
Manteremos uma pasta chamada `docs/postman/` na raiz do monorepo contendo dois arquivos exportados:
1.  **Collection (`Beauty_Wellness.postman_collection.json`):** Contendo as requisições organizadas por pastas (Auth, Catalog, Booking).
2.  **Environment (`Local_Env.postman_environment.json`):** Contendo as variáveis de ambiente.
    *   *Mágica do Postman:* O endpoint de `POST /api/auth/login` terá um script na aba *Tests* que captura o token da resposta e injeta automaticamente na variável de ambiente `{{access_token}}`. Assim, as próximas requisições já estarão autenticadas.

# Parte 2: README.md - Auth Service

Crie o arquivo `auth-service/README.md` com o seguinte conteúdo:

```markdown
# 🔐 Auth Service (Identity & Access Management)

Este microsserviço é o provedor central de identidade do sistema Beauty & Wellness. Desenvolvido sob os princípios da **Clean Architecture**, ele é responsável por gerenciar credenciais, validar senhas via hash (BCrypt) e emitir *JSON Web Tokens* (JWT) utilizando criptografia assimétrica (RSA).

## 🚀 Tecnologias Utilizadas
* **Java 21** / **Spring Boot 3.x**
* **Spring Security** (Autenticação Stateless)
* **PostgreSQL** (Persistência relacional isolada)
* **Flyway** (Migrations de Banco de Dados)
* **Nimbus JOSE + JWT** (Geração de tokens RSA)
* **Springdoc OpenAPI** (Documentação Swagger)

## 📁 Estrutura Clean Architecture
O código está estritamente dividido para garantir independência de frameworks nas regras de negócio:
- `core/`: Entidades puras, Use Cases (Regras de negócio) e Ports (Interfaces). **100% coberto por TDD.**
- `application/`: DTOs e mapeadores.
- `infrastructure/`: Controladores REST, adaptadores do Spring Data JPA, configurações de segurança.

## ⚙️ Como Executar Localmente
1. Certifique-se de que o banco PostgreSQL está rodando (via `docker-compose` na infra).
2. Execute a aplicação ativando o profile local:
   ```bash
   ./mvnw spring-boot:run -Dspring-boot.run.profiles=local
   ```
3. A API subirá na porta `8081`.

## 📚 Documentação da API (Swagger)
A documentação detalhada dos endpoints, payloads e códigos de erro pode ser acessada diretamente via:
👉 `http://localhost:8081/swagger-ui.html` (ou agregada no API Gateway na porta 8080).
```

# Parte 3: README.md - API Gateway

Crie o arquivo `api-gateway/README.md` com o seguinte conteúdo:

```markdown
# 🚪 API Gateway (Edge Service)

O API Gateway é a porta de entrada única e o escudo do ecossistema Beauty & Wellness. Desenvolvido de forma não-bloqueante (Reativa) com **Spring Cloud Gateway**, ele centraliza o roteamento, a política de CORS e a **validação de segurança JWT**.

## 🚀 Responsabilidades
1. **Roteamento Dinâmico:** Encaminha chamadas (`/api/auth/**`, `/api/bookings/**`) para os microsserviços adequados escondidos na rede interna.
2. **Offloading de Autenticação:** Intercepta todas as rotas protegidas e valida a assinatura matemática e expiração do JWT (via Chave Pública RS256) antes de repassar a requisição, poupando os microsserviços dessa carga.
3. **Agregação de Swagger:** Unifica a documentação OpenAPI de todos os microsserviços em uma única interface gráfica.

## 🛠️ Tecnologias Utilizadas
* **Java 21** / **Spring Boot 3.x**
* **Spring Cloud Gateway** (Project Reactor / WebFlux / Netty)
* **Springdoc OpenAPI** (Agregador Swagger UI)

## ⚙️ Como Executar Localmente
1. Suba os microsserviços de backend que receberão as requisições.
2. Execute a aplicação:
   ```bash
   ./mvnw spring-boot:run -Dspring-boot.run.profiles=local
   ```
3. O Gateway subirá na porta principal `8080`.

## 📚 Swagger UI Centralizado
Para visualizar todos os endpoints do sistema consolidados, acesse:
👉 `http://localhost:8080/swagger-ui.html`
```
