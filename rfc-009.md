## 1. Sumário Executivo
Esta RFC define a padronização dos `Dockerfiles` utilizando **Multi-stage Builds** para os microsserviços do sistema Beauty & Wellness. Além disso, propõe a criação de um `docker-compose.yml` na raiz do monorepo responsável por orquestrar tanto a infraestrutura de apoio (Bancos de Dados e Mensageria) quanto as próprias aplicações, garantindo o princípio de *Dev/Prod Parity* (Paridade entre Desenvolvimento e Produção) do 12-Factor App.

## 2. Contexto e Motivação
Para que o desenvolvimento local não sofra com a síndrome do *"na minha máquina funciona"*, precisamos isolar as aplicações e suas dependências. Como temos um monorepo, a orquestração precisa subir o ecossistema inteiro com um único comando (`docker compose up -d`), injetando as variáveis de ambiente corretas e mapeando as chaves criptográficas (RSA) de segurança.

## 3. Estrutura de Diretórios Alvo

A estrutura final no monorepo após esta implementação ficará assim:

```text
beauty-wellness-system/
 ├── infra/
 │    ├── certs/                 # Chaves RSA (private_key.pem, public_key.pem)
 │    └── init-scripts/          # Scripts SQL para criar os databases no Postgres
 │
 ├── api-gateway/
 │    └── Dockerfile             # Multi-stage build do Gateway
 ├── auth-service/
 │    └── Dockerfile             # Multi-stage build do Auth
 ├── catalog-service/
 │    └── Dockerfile             # Multi-stage build do Catalog
 │
 └── docker-compose.yml          # O grande orquestrador do monorepo
```

## 4. Padronização dos Dockerfiles (Multi-stage Build)

Para garantir imagens leves e seguras (sem o código fonte ou o Maven na imagem final), todos os três microsserviços utilizarão um `Dockerfile` padronizado em dois estágios.

Crie este arquivo dentro de cada módulo (`api-gateway/Dockerfile`, `auth-service/Dockerfile`, `catalog-service/Dockerfile`), alterando apenas os nomes se necessário (assumindo uso do Maven Wrapper `mvnw`):

```dockerfile
# ESTÁGIO 1: Build (Compilação)
FROM eclipse-temurin:21-jdk-alpine AS builder
WORKDIR /build

# Copia os arquivos de dependência primeiro (para cache do Docker)
COPY .mvn/ .mvn/
COPY mvnw pom.xml ./
# Baixa as dependências offline
RUN ./mvnw dependency:go-offline

# Copia o código fonte e compila
COPY src/ ./src/
RUN ./mvnw clean package -DskipTests

# ESTÁGIO 2: Run (Execução)
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app

# Cria um usuário não-root para segurança
RUN addgroup -S spring && adduser -S spring -G spring
USER spring:spring

# Copia apenas o .jar gerado no estágio 1
COPY --from=builder /build/target/*.jar app.jar

# Expõe a porta (A porta real será sobrescrita no docker-compose)
EXPOSE 8080

# Ponto de entrada otimizado para containers
ENTRYPOINT["java", "-XX:MaxRAMPercentage=75.0", "-jar", "app.jar"]
```

## 5. Orquestração: O arquivo `docker-compose.yml`

Na raiz do seu projeto, crie o arquivo `docker-compose.yml`. Ele orquestrará as redes, volumes, infraestrutura e as aplicações.

### 5.1. Script de Inicialização de Banco de Dados
Como rodaremos **um único container PostgreSQL** localmente por questões de performance, mas temos microsserviços que exigem bancos separados (`auth_db` e `catalog_db`), precisamos de um script de inicialização.

Crie o arquivo `infra/init-scripts/init.sql`:
```sql
CREATE DATABASE auth_db;
CREATE DATABASE catalog_db;
```

### 5.2. O `docker-compose.yml` Completo

```yaml
version: '3.8'

services:
  # ==========================================
  # 1. INFRAESTRUTURA
  # ==========================================
  postgres:
    image: postgres:16-alpine
    container_name: bw-postgres
    ports:
      - "5432:5432"
    environment:
      POSTGRES_USER: admin
      POSTGRES_PASSWORD: admin123
      # O Postgres executa tudo que estiver em /docker-entrypoint-initdb.d na 1ª vez
    volumes:
      - pgdata:/var/lib/postgresql/data
      - ./infra/init-scripts/init.sql:/docker-entrypoint-initdb.d/init.sql
    networks:
      - bw-network
    healthcheck:
      test:["CMD-SHELL", "pg_isready -U admin"]
      interval: 5s
      timeout: 5s
      retries: 5

  rabbitmq:
    image: rabbitmq:3-management-alpine
    container_name: bw-rabbitmq
    ports:
      - "5672:5672"   # Porta da aplicação
      - "15672:15672" # Porta do painel web
    environment:
      RABBITMQ_DEFAULT_USER: guest
      RABBITMQ_DEFAULT_PASS: guest
    networks:
      - bw-network

  # ==========================================
  # 2. MICROSSERVIÇOS (Aplicações)
  # ==========================================
  api-gateway:
    build: 
      context: ./api-gateway
      dockerfile: Dockerfile
    container_name: bw-api-gateway
    ports:
      - "8080:8080"
    environment:
      - SPRING_PROFILES_ACTIVE=docker
      - AUTH_SERVICE_URI=http://auth-service:8081
      - CATALOG_SERVICE_URI=http://catalog-service:8083
      - RSA_PUBLIC_KEY_PATH=file:/app/certs/public_key.pem
    volumes:
      - ./infra/certs:/app/certs:ro # Read-only para as chaves
    networks:
      - bw-network
    depends_on:
      - auth-service
      - catalog-service

  auth-service:
    build: 
      context: ./auth-service
      dockerfile: Dockerfile
    container_name: bw-auth-service
    ports:
      - "8081:8081"
    environment:
      - SPRING_PROFILES_ACTIVE=docker
      - DB_HOST=postgres
      - DB_PORT=5432
      - DB_NAME=auth_db
      - DB_USER=admin
      - DB_PASS=admin123
      - RSA_PRIVATE_KEY_PATH=file:/app/certs/private_key.pem
    volumes:
      - ./infra/certs:/app/certs:ro
    networks:
      - bw-network
    depends_on:
      postgres:
        condition: service_healthy

  catalog-service:
    build: 
      context: ./catalog-service
      dockerfile: Dockerfile
    container_name: bw-catalog-service
    ports:
      - "8083:8083"
    environment:
      - SPRING_PROFILES_ACTIVE=docker
      - DB_HOST=postgres
      - DB_PORT=5432
      - DB_NAME=catalog_db
      - DB_USER=admin
      - DB_PASS=admin123
      - RABBIT_HOST=rabbitmq
    networks:
      - bw-network
    depends_on:
      postgres:
        condition: service_healthy

# ==========================================
# 3. REDES E VOLUMES
# ==========================================
networks:
  bw-network:
    driver: bridge

volumes:
  pgdata:
```

## 6. Gestão das Chaves Criptográficas (RSA)

Para que o Auth Service assine o JWT e o API Gateway valide a assinatura, é obrigatório gerar o par de chaves RSA e colocá-lo na pasta `infra/certs/` **antes** de subir o Docker Compose.

**Instruções para o Terminal:**
```bash
mkdir -p infra/certs
cd infra/certs

# 1. Gera a chave privada (Para o Auth Service)
openssl genrsa -out private_key.pem 2048

# 2. Gera a chave pública a partir da privada (Para o API Gateway)
openssl rsa -in private_key.pem -pubout -out public_key.pem
```
*(Nota: O docker-compose mapeia essa pasta `infra/certs` como um Volume para dentro dos containers, permitindo que o Spring Boot leia os arquivos sem precisar compilar as chaves dentro da imagem Docker).*
